Legal Document RAG
on LegalBench-RAG 2024

Finding the right clause is not the same as answering the question. A small evaluation shows where contract-aware retrieval works and where evidence is lost between search and response.

Analysis by Rishabh Jain. The benchmark was published on 19 August 2024. Its underlying contracts span different years; 2024 is not a contract date or an evaluation-run date.

01 / Dataset

Four collections, very different documents.

The project uses the LegalBench-RAG corpus and reference spans. The local corpus and question counts below describe this project, not every version of the benchmark.

The 644 documents include non-disclosure agreements, commercial contracts, merger agreements and privacy policies. CUAD supplies most documents. MAUD supplies most text because its agreements are much longer.

Length changes the retrieval problem.

The shortest document has 219 words and the longest has 156,104. The median is 5,494 words, compared with a mean of 15,248. Passing whole documents to the answer model would obscure the relevant clause and increase the context sent to the API.

Availability limits the evaluation pool.

Of 6,695 extracted questions, 6,033 have an available source document. Ten of those questions were evaluated. PrivacyQA contributes three documents to the corpus but no questions to this evaluated sample.

02 / Method and engineering

Identify the contract before searching its clauses.

A question names a contract before a semicolon. That description and the legal question serve different purposes.

  1. Preserve the legal wording.Cleaning keeps casing and negation. Contact details and separator lines are replaced with spaces, and whitespace is normalised. An offset map preserves the connection to the original source characters. Stop-word removal is used only in exploratory analysis.
  2. Create two representations of each document.LangChain's recursive text splitter creates windows of up to 1,500 characters with a 200-character overlap. A separate document card contains the file name and first 1,500 characters. This gives 63,914 chunks and 644 cards.
  3. Build separate vector collections.OpenAI text-embedding-3-small embeds the chunks and cards. Chroma persists them in two local collections. The stored index is reused rather than rebuilt for every question.
  4. Route and retrieve.The contract description selects the closest document card. The legal question then searches only that contract's chunks. The five highest-ranked chunks become the answer context.
  5. Generate a constrained answer.OpenAI gpt-4o-mini runs at temperature zero. The prompt asks for exact quotes, source citations and abstention when the evidence is insufficient. If no excerpts are found, the chain abstains without a generation call.
  6. Evaluate retrieval separately from generation.Reference-span overlap supplies Hit@5 and MRR@5. Ragas uses an LLM judge for faithfulness, answer relevancy, context precision and context recall. These measures answer different questions and should not be combined into one accuracy score.

03 / Results

Retrieval is stronger than the final answer.

The sample contains three ContractNLI, four CUAD and three MAUD questions, selected with seed 42.

Nine retrieval hits produced only eight non-abstaining responses.The model abstained twice. At least one retrieval hit therefore did not lead to an answer. A partial span overlap can still be insufficient evidence.

The evidence is often present.

Hit@5 is 0.900 and context recall is 0.871. This supports retaining document-aware retrieval as the baseline. It does not establish that the entire benchmark is solved.

Evidence use needs more attention.

Answer relevancy is 0.525, while faithfulness is 0.802. A response can remain close to the supplied excerpts without directly answering the question. High faithfulness alone is not a measure of usefulness.

MeasureInterpretation
Hit@5At least one of the five retrieved chunks overlaps a reference text span.

04 / Diagnostics

Look beyond the averages.

The ten saved rows expose different failure modes. A single aggregate score would conceal them.

  • ContractNLI 344 is the only retrieval miss. Its faithfulness score is still 1.000, while recall and relevancy are zero. This is why faithful wording must not be confused with successful question answering.
  • CUAD 3537 has a first-ranked retrieval hit and context recall of 1.000, but both answer relevancy and faithfulness are zero. Its answer should be inspected before changing the retrieval strategy.
  • Four of the nine hits first overlap the reference below rank one. Two first overlap at rank five. This motivates a controlled re-ranking experiment, although the current run does not measure its benefit.

05 / Conclusion

A useful baseline, not a legal decision system.

The next work should isolate errors before adding more infrastructure.

What the project establishes.

The implementation demonstrates a complete route, retrieve and answer workflow with source offsets and saved evaluation results. On this ten-question sample, it usually retrieves text that overlaps the reference. The weaker answer relevancy shows that retrieval coverage and useful responses are separate goals.

What a project owner should prioritise.

  1. Classify failures before changing models.Review the selected contract, retrieved span and generated response for each question. Label routing, ranking, incomplete-context and answering failures separately. This avoids treating every low score as an embedding problem.
  2. Test one intervention at a time.Compare re-ranking, richer document cards and clause-aware chunking against the current baseline. Keep the question set fixed and record both improved and regressed cases. These are proposed experiments, not demonstrated improvements.
  3. Keep abstention tied to evidence.Do not remove cautious behaviour merely to increase response rate. Review when the retrieved context genuinely supports an answer, then test prompt changes against that judgement.
  4. Expand evaluation before claiming reliability.Use a larger, balanced sample across collections and question types. Add human review of citations and factual claims, and record latency and API usage. The current report does not measure production cost, throughput or legal accuracy.

Limits that change the interpretation.

  • One question changes Hit@5 by ten percentage points. Collection filters contain only three or four cases and should not be used to rank datasets.
  • Routing selects a single contract. A routing mistake can exclude the correct evidence entirely.
  • Ragas uses an LLM judge. Scores and generated responses can vary between runs despite a fixed sample and temperature zero.
  • The system is a research prototype. Its generated answers are not legal advice and should not replace qualified review.
